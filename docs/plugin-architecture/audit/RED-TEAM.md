## Original Audit Verdict: **DO NOT SHIP** *(Superseded by `fix/redteam-1` Remediation Above)*

Even under a *"curated first-party only / careless-plugin"* threat model—and **certainly** for any third-party or community plugin—the Burrow plugin subsystem is **not ready to ship**:

1. **PostgreSQL 17 containment—explicitly claimed as DB-enforced in `READINESS-v2.md`—is broken in multiple independent ways**: the DDL event triggers `burrow_enforce_plugin_ddl()` and `burrow_enforce_plugin_drop()` are marked `SECURITY DEFINER`, which flips `current_user` to the superuser owner and causes both triggers to `RETURN` on line 1 (`CREATE FUNCTION` and `CREATE TRIGGER` execute freely as a plugin role). Meanwhile `ARRAY[']']` desyncs the JS statement splitter so `SELECT ARRAY[']']; RESET ROLE; SELECT ... FROM public."user"` executes as the connection role, migrations can run `RESET ROLE` (`skipLexerForTest`), schema ownership (`ALTER SCHEMA ... OWNER TO`) lets any plugin self-regrant `CREATE ON SCHEMA` at runtime, `GRANT REFERENCES(id)` enables permanent core deletion DoS (`23503`) plus ID enumeration, `pg_advisory_lock` lets plugins deadlock core migrations, and `statement_timeout` is unset (`0`).
2. **Application & Admin Governance flaws affect even careless / first-party deployments**: Worker `c.env` secrets (`BETTER_AUTH_SECRET`, raw `DB` handle) are exposed to external plugin routes; any arbitrary workspace `owner` on a multi-workspace instance can disable/enable instance-wide plugins (`POST /api/plugins/:id/toggle`); zero-workspace authenticated users can enumerate plugin `configKeys` and `network` allowlists (`GET /api/plugins`); third-party plugins start `enabled: true` without operator consent and can mutate `ctx.manifest` post-registration; external plugins can hijack core adapter slots across split `loadServerPlugins()` calls or spoof `'public-sharing'` to disable core routes.
3. **SSRF, XSS/CSP, SQLite/D1 lexer, Logger, Event Bus, Storage, Resource caps, and `plugin:validate` each have reproducible bypasses** documented below.

*(A companion red-team assessment of the separate private hosting application lives in its own repository.)*

## Residual Risks (Cannot Be Fixed In-Process)

Because server plugins execute as **ordinary ESM/JS modules inside the same Node.js or Cloudflare Worker isolate** as Burrow core (verified in [`context-routes-authz.test.ts`](file:///d:/Burrow-private-public/Burrow/tests/redteam/context-routes-authz.test.ts#L569-L578)):
1. **Arbitrary `process.env` / `globalThis` / Node built-in access**: Any in-process plugin (or compromised transitive npm package) can read `process.env.BETTER_AUTH_SECRET`, `process.env.DATABASE_URL`, invoke `node:fs` / `node:child_process`, or import `@burrow/core` directly, bypassing `PluginDb`, `ctx.fetch`, `ctx.storage`, `ctx.config`, and `@burrow/eslint-plugin` (via dynamic property lookup, `Buffer`, CJS wrappers, or transitive dependencies).
2. **Prototype / Monkey-Patching & Memory/CPU DoS**: A plugin can monkey-patch `globalThis.fetch`, `Array.prototype`, or core module exports, register persistent timers, leak heap memory, or block the single-threaded JS event loop (`while (true) {}`), crashing or freezing the entire host process.
3. **SQLite / D1 lacks engine ACLs**: Every plugin and core table share one SQLite/D1 database without roles or `GRANT`/`REVOKE`; any raw driver handle obtained in-process reads/writes all tables without constraint.
4. **Implication**: Even after fixing all 28 findings above, **untrusted third-party plugins must NEVER be executed in-process**. True multi-vendor isolation requires out-of-process execution (isolated OS containers, Worker-per-plugin Service Bindings, or sandboxed V8 isolates with capability RPCs).

## Coverage Gaps

- **Live Browser DOM Rendering**: Sanitizer bypasses were tested directly via SDK functions rather than mounted inside headless Chromium executing full `CardPanel`, `Sidebar`, and `PluginsSection` React renders.
- **External Object Storage Backends**: Tested `LocalStorageAdapter` and in-memory mocks; live `S3StorageAdapter` and remote Cloudflare R2 presigned/bucket behavior were not exercised against S3/R2 emulators.
- **Automated Grammar Fuzzing**: Crafted manual SQL lexer & sanitizer bypass payloads rather than running continuous coverage-guided fuzzing (e.g. Jazzer.js / fast-check over `plugin-db.ts` and `packages/sdk`).
- **Node VM / Worker Multi-Isolate Timing**: Did not test sustained event-loop starvation or concurrent request flooding across multi-core cluster deployments.
